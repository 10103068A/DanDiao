# 公會活動抽獎系統

依 `公會活動抽獎系統-規格書.md` v1.4 實作。純靜態網頁，無建置流程、無框架、無第三方函式庫。

## 檔案結構

```
index.html      首頁＝簡易抽獎（獨立小工具，不讀寫任何雲端資料）
history.html    歷史活動（公開，可匯出各場中獎名單）
admin.html      管理者頁面（新增活動、拉取報名、截止報名、報名異常 / 成員名單）
event.html      進行中活動頁（簽到、抽獎、直播模式、存進歷史）
privacy.html    隱私權政策（OAuth 同意畫面要求）
terms.html      服務條款（OAuth 同意畫面要求）
serve.js        本機開發用靜態伺服器

css/style.css
js/config.js    設定：密碼、DEMO_MODE、Google 用戶端 ID / API 金鑰 / 檔案 ID
js/util.js      共用工具（DOM、翻牌、收合、匯出檔案）
js/lottery.js   crypto 真亂數 + Fisher–Yates 洗牌
js/matching.js  報名資料比對與異常分類（§10）
js/google.js    GIS 授權 + Drive / Forms API（§4 §8.2）
js/store.js     儲存抽象層（DEMO / Drive）+ 表單服務 + DEMO 假資料
js/admin.js     管理頁邏輯
js/event.js     進行中活動頁 + 抽獎 + 直播模式
js/simple.js    簡易抽獎
data/seed.json  DEMO 模式的初始資料（32 名成員 + 1 場歷史活動）
```

`data/` 只供本機 DEMO 使用，已列入 `.gitignore`，不會進 repo；Drive 模式不會讀到它。

## 執行

不能用 `file://` 直接開，`fetch` 會被 CORS 擋。

```bash
node serve.js
```

會印出網址（預設 http://localhost:4173），換 port 就在後面加數字。管理頁的共用密碼是 `js/config.js` 的 `PASSCODE`。

## 兩種模式

`js/config.js` 的 `DEMO_MODE`：

目前設定為 **Drive 模式**（`DEMO_MODE = false`）。

| | DEMO | Drive |
|---|---|---|
| 資料 | localStorage | Google Drive 三個 JSON |
| 表單 | 產生假連結、假回覆 | 真的 Google Forms |
| 「連線 Google」 | 模擬帳號，直接可寫入 | 真的 OAuth |
| 需要設定 | 無 | Client ID（必要）、API 金鑰、三個檔案 ID |

DEMO 模式的假回覆會刻意包含五類異常樣本（不在名單、重複報名、防呆題答錯、逾時、公會不符），用來驗證比對邏輯。

## 走一遍完整流程（DEMO）

1. `admin.html` → 輸入密碼 → 按「連線 Google」
2. 新增活動：填日期、時間（預設 22:00）、名稱 → `＋ 建立`（自動產生報名表單與防呆題）
3. 按「拉取報名資料」→ 右欄的報名異常面板依類別列出，每類可「複製清單」；報名要關閉時按「截止報名」
4. 「成員」分頁表格唯讀，可搜尋與排序；異動走「更新成員（匯入名單）」或「＋ 新增成員」，完成後自動存檔，另可「匯出名單」
5. `event.html` → 「產生簽到表單」（顯示 4 位數簽到碼）→ 「拉取簽到」
6. 獎項表格最後一列直接輸入名稱按 Enter 就新增一列；`⠿` 拖曳排序；「可重複」＝加碼
7. **點選要抽的獎項**（右邊會擺上等同名額數的蓋牌），按「阿拉花光」翻牌抽出。獎項可任意順序抽，不必由上而下。每抽完一項自動寫入 localStorage 暫存
8. 「直播模式」切換高對比大字畫面（Esc 離開）
9. 「儲存到歷史活動」→ 一次寫入中獎結果與歷史、更新成員計數、清空進行中活動
10. `history.html` 展開該場活動，可看到參加者名單與中獎結果，並可「匯出中獎名單」（CSV）

`index.html`（首頁）是獨立的簡易抽獎，分三欄：**獎項 / 名單 / 抽獎**。可一次建好多個獎項，點選要抽的那項再按「阿拉花光」，操作方式與活動頁一致，「可重複」也是逐項設定。獎項與名單暫存在 `sessionStorage`：切分頁、重新整理都保留，關掉分頁就清掉 —— 不寫檔、不進雲端。

管理頁 topbar 的「重置 DEMO 資料」可還原初始狀態。

## 已實作的規格重點

**抽獎**

- 採 crypto 真亂數，**刻意不可重現**：同一份名單重抽必然得到不同結果，避免「重抽卻抽出同一批人」被誤認為黑箱（不存種子、不提供重算驗證）
- 獎項可任意順序抽（點選哪個抽哪個）。非加碼獎項的池一律排除「其他所有已抽出獎項」的得獎者，與抽的先後無關
- 逐項 `allowRepeat`：加碼獎項可抽到其他獎項的中獎者，但同一獎項內不重複；加碼得獎者一樣會被其他非加碼獎項排除
- 池中人數不足時抽到池空，多出來的牌翻成「—」並顯示缺額提示
- 已抽出的獎項鎖定，不可修改、刪除、移動，也不能被插隊到它的位置
- 揭曉用翻牌：先擺上蓋著的牌，再一張一張翻開（牌數多時翻快一點）；直播模式的牌會放大
- 抽獎過程零 API 呼叫，每步寫入 localStorage，重整不遺失；正式寫檔只在「儲存到歷史活動」發生

**報名 / 成員**

- `status` / `matchedId` 為衍生欄位，每次拉取報名資料全部重算；新人補進成員庫後重拉即自動轉正（§10.1.1）
- 截止報名把當下時間記為截止時間，之後送出的報名在下次拉取時標為逾時（§8.3）
- 報名 / 簽到異常純顯示，只提供「複製清單」，不提供任何處理功能（§10.3）
- 成員表格唯讀，所有異動只能經由匯入名單或新增成員，兩者都需會長權限
- 成員名單檔是純文字（記事本可編輯），一行一人 `角色ID,公會`；匯入為整份取代，檔案裡沒有的人會被移除，參與 / 請假 / 異教徒次數由系統累計，既有成員沿用、新成員從 0 起算
- 歸檔時的成員計數更新（§10.4）

**權限 / 其他**

- 寫入按鈕在未連線時顯示 disabled 並標註「需會長權限」，而非隱藏（§3.2）
- 「連線 Google」只在管理頁；access token 存進 sessionStorage，其他分頁沿用同一次授權，關掉分頁即失效
- 直播模式：隱藏簽到碼、寫入按鈕與異常區；加碼獎項標示；遵守 `prefers-reduced-motion`（關閉翻牌動畫直接顯示）
- 匯出 / 匯入全部資料（§13）

## 公會名稱

頁首的「蛋雕教」是純 CSS 文字（`css/style.css` 的 `.brand`），不是圖片，所以任何解析度都清楚、也不會拖慢載入。
要改名稱就直接改四個 HTML（index / history / admin / event）裡的 `<span class="guild">`；要換配色改 `.brand` 的 `background` 與 `.guild` 的 `background`（金色漸層）。

## 切到 Drive 模式要做的事

1. Google Cloud 建專案，啟用 **Forms API** 與 **Drive API**
2. 建立 OAuth 用戶端 ID（網頁應用程式），已授權的 JavaScript 來源填部署網址與 `http://localhost:4173`
   → 填入 `CONFIG.GOOGLE.CLIENT_ID`
3. 建立 API 金鑰，設 HTTP 參照網址限制與 Drive API 限制 → 填入 `API_KEY`
4. `DEMO_MODE = false`
5. 開管理頁 → 用**會長帳號**按「連線 Google」→ 按「創立教典紀事」（已有聖所時是「另擇聖所安置」）
   → 程式會建立三個 JSON 並設為「知道連結的人可讀」，畫面印出可直接貼上的 `FILE_IDS` 區塊
6. 把那段貼進 `CONFIG.GOOGLE.FILE_IDS`
7. OAuth 同意畫面發布為「正式」，否則只有「測試使用者」清單裡的帳號能登入

> 換人當會長就是重跑第 5、6 步：新會長按「另擇聖所安置」在自己帳號建三份新檔案，再把新的 ID 貼回 `config.js`。
> 舊資料可先用「匯出全部」帶出、再用「匯入」灌進新聖所。

> **不要手動在 Drive 建那三個檔案。** `drive.file` scope 只涵蓋「本程式建立的檔案」，手動建的檔案會長自己也寫不進去（Drive 回 404）。

規格 §15 風險 1（跨來源讀取公開 Drive 檔案）已於 2026-09-09 實測通過；風險 2（`setPublishSettings` 行為）待建立第一張表單時驗證。

## 部署（GitHub Pages）

純靜態、無建置流程，推上 `main` 就是部署：

```bash
git add -A && git commit -m "更新內容" && git push
```

repo 的 Settings → Pages → Source 選 `Deploy from a branch`、分支 `main`、資料夾 `/ (root)`，
約一分鐘後上線。免費帳號需 repo 為 public。

換了網址記得同步兩件事，否則線上按「連線 Google」會被擋：

- OAuth 用戶端的**已授權的 JavaScript 來源**加上新網址
- API 金鑰的 **HTTP 參照網址限制**加上新網址

## 隱私權與服務條款

`privacy.html` / `terms.html` 是 Google OAuth 同意畫面（品牌頁）要求填寫的兩個連結，
內容依本系統實際行為撰寫：資料存在會長個人 Drive、成員瀏覽不需登入、
`drive.file` 只涵蓋本程式建立的檔案、token 只存 sessionStorage。
改動授權範圍或資料流向時，記得一併更新這兩頁。
